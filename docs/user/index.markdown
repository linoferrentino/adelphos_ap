## Introduction

Adelphos (ἀδελφός, the ancient Greek word for "brother") is a closed system
that enables users to exchange goods and services using a virtual currency.
The system is able to handle the shipping too, by using the members of the
system as partial carriers of an object from the seller to the buyer, so
that *no* external carrier (like FedEx, DHL, etc.) is needed.

This is why adelphos is *closed*.


There are other systems like this, as the _time banks_ and the _LETS_
system, which is now evoluted in credit commons which enables system to
federate themselves and exchange credit.

The real difference of adelphos between similar systems are:

    * Adelphos does the routing of the object, and also the shipping costs
      are handled with the virtual currency, that is it *unifies* the
      *real* and the *virtual*

    * Adelphos lets communities of users to share gains and losses, based
      on their "brotherhood" (hence the name).

You can think of it like the union of eBay, Amazon and DHL in the same
system, with the added bonus that it is free (free as *free speech* and
*free beer*), and all of that happens *without* the use of real money,
__ever__, not even when we ship the object, because the system is __a
closed ecosystem__ (closed with respect to the money, open with respect to
the people).


## A physical router based on a web of trust

The main difference from other similar systems (LETS, CreditCommons,
Ripple) is that Adelphos is a closed ecosystem: it does not rely on
external carriers: if a user sells an object it *creates* also the shipping
of the item to the buyer using a chain of steps much like packets in a IP
protocol.

Each steps has a dikastes (δικαστής, the Greek word for _judge_) and a
diakonos (διάκονος, the Greek word for _servant_) who will handle the
routing one leg of a time and each leg is registered in the system with its
cost.

Adelphos is also able to limit the amount of trust (credit) which we give
to the system and that the system gives to us; in this way the seller is
limited by the system to only sell until a certain amount (so that his
credit is secured) but also the buyer is limited to a certain amount (so
that he cannot exploit the system over a certain point).

These limits are changed gradually by the users' feedback, so the main
objective of adelphos is thus to allow users to form an increasingly strong
web of trust.


## A trust amplifier

Since ancient times humans have invented ways to amplify their powers;
fire, weapons, levers, machines, cars, planes, and now computers and
A.I.  are all tools to enhance various human capabilities, like the
ability to lift weights, to travel, to kill, to store and process
information.

But no significant steps have made to amplify their capacity to love and to
care for other people in a objectively way. Religions, spiritual teaching have
done a great deal of work in educating people to care for people far from our
perceived reality.

Exiting the family borders trust drops drastically, like the bottom of an
ocean; sometimes in small groups trust survives, or, ironically, in "mafia"
style families united by crime.

In the 'civil' world little has been achieved; wars, oppressions and inequality
are still present; we do not fall into the trap of saying that "the past was
better", but certainly it was not "worse".

Sometimes we are still as we were in the tribes, closed and wary.

But how would it be if we created a system that helped humans to trust
each other? We should design a system that is able to mimic the way in
which humans care for each other.

This is the core of adelphos, We can define it a **trust amplifier**.

As a phone is able to carry our voice to the other part of the globe,
adelphos is able to up-level our natural trust in the closest circle
(the family) to bigger and bigger groups.

This is done by the user themselves who organize themselves (hence the
word self-organizing) into bigger structures which are similar to the
ones at the lower levels (hence the word fractal).

There have been trials of similar systems, notably the Credit Commons
protocol, but they have not had a widespread use probably because they lack
the ability to measure trust and to give to end users a *closed* system
which allows them to close the circle from the buyer to the seller, even if
they are geographically separated.

## Activity Pub and Adelphos

Each Adelphos instance is a federated instance which uses Activity Pub to
communicate

Activity Pub has been chosen because:

   * it is an open standard

   * it allows the authentication of messages

   * it saves me from the burden to write an UI, because I rely on Mastodon
     (the _de facto_ standard in the Fediverse to handle users) to send
     messages to fediverse users.
